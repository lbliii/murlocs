# Chirp and Kida paired-pilot audit

Audit date: 2026-07-17

This read-only audit compares the existing Chirp and Kida `.stewards` networks with Murlocs v0.1.
The objective is not to redesign their guidance. It is to identify the smallest reusable migration
contract that can preserve both repositories without importing project-specific policy into the
Murlocs core.

## Baseline

Both repositories already compile `AGENTS.md` maps from a TOML manifest and validate graph edges,
proof wiring, source coverage, generated drift, and active-context budgets. Their projectors and
verifiers passed during the audit.

| Property | Chirp | Kida |
| --- | ---: | ---: |
| Generated maps | 34 | 24 |
| Registered checks | 36 | 29 |
| Invariants | 50 | 49 |
| Machine-backed | 39 | 43 |
| Manual | 10 | 4 |
| Explicitly unverified | 1 | 2 |
| Judgment sections | 9 | 6 |
| Total generated bytes | 53,549 | 48,332 |
| Largest active chain | 14,011 bytes | 16,023 bytes |
| Active-chain budget | 24,576 bytes | 24,576 bytes |

The audit ran these non-executing maintenance checks in each repository:

```text
python3 .stewards/project.py --check
python3 .stewards/verify.py --coverage
```

Chirp reported all 34 maps current and all 50 invariants valid. Kida reported all 24 maps current
and all 49 invariants valid. These commands inspect registered checks but do not execute them.

Kida had unrelated user changes on its active feature branch during the audit. No pilot repository
files were changed, and later adoption must use a clean isolated worktree.

## What already maps cleanly

The repositories share a common core with Murlocs:

- one manifest as the reviewed source of truth;
- nested maps with a maximum active-context budget;
- stable scope identifiers, point-of-view text, guardrails, and typed edges;
- invariants with command, manual, or explicitly unknown backing;
- registered checks with an invocation, proof location, and optional textual anchor;
- source-domain coverage and deterministic drift verification.

The mechanical vocabulary conversion is straightforward: legacy `steward` becomes `scope`,
`machine` becomes `command`, `none` becomes `unknown`, and `coverage_roots` moves under the Murlocs
coverage table. A legacy map path also has to split into Murlocs' separate scope path and map path.

Murlocs already improves one important boundary: its content-addressed lockfile refuses unmanaged,
modified, and orphaned generated maps. The migration workflow must preserve that protection rather
than bypassing it.

## Parity gaps

| Existing contract | Murlocs v0.1 behavior | Required migration decision |
| --- | --- | --- |
| `search_policy` is rendered as first-class context discipline. | No dedicated field or rendered section. | Preserve it as structured manifest data. |
| `judgment` renders `Advocate`, `Do Not`, and `Serves`. | No advisory-judgment model. | Add a non-enforceable structured section; never convert it into invariants. |
| Ownership is grouped as code, tests, and docs. | Ownership is a flat string list. | Preserve ownership categories or define a lossless typed replacement. |
| Severity uses P0, P1, and, in Kida, P2. | Severity accepts critical, important, and advisory. | Define and report an explicit mapping; do not silently reinterpret severity. |
| Scoped maps tell agents when not to open maintenance context. | Generated maps link the protocol but omit ordinary-task context rules. | Add a compact generated context-discipline contract. |
| The root map summarizes every scope and its proof ratio. | The root lists checks but not the network inventory. | Decide whether the inventory remains generated or moves to `explain`; preserve discoverability. |
| A check's `proof_contains` is optional. | `proof_contains` is required. | Report missing anchors as debt and require an explicit resolution policy. |
| Legacy verification checks local paths named in command strings. | Murlocs verifies the configured proof location only. | Add conservative command-path liveness checks without executing commands. |
| Coverage recognizes a domain containing nested Python sources. | Coverage checks direct files in a candidate directory. | Make source-domain detection recursive and suffix-aware. |
| Kida requires every scope to own at least one invariant. | Murlocs permits scopes without invariants. | Make this a configurable policy instead of a universal assumption. |
| Existing `AGENTS.md` files are generated but not owned by Murlocs. | Compilation correctly refuses them as unmanaged. | Import and adoption must remain separate, explicit operations. |
| `CLAUDE.md` is durable, hand-authored development guidance. | No adapter or ownership policy exists yet. | Inventory it as user-owned; do not overwrite it during the pilot. |

Proof anchoring is the largest immediate compatibility issue. Thirty-three Chirp checks and five
Kida checks omit `proof_contains`. Their legacy verifiers still establish that each configured
location exists, but that is weaker than Murlocs' intended proof-anchor contract. Import must expose
this difference rather than inserting an empty anchor or upgrading the claims.

## Migration shape

The safe workflow is intentionally staged:

1. Inventory existing instruction files, manifests, generated markers, and ownership conflicts.
2. Translate the legacy manifest into a candidate Murlocs manifest without writing maps.
3. Emit a loss report for fields, severity mappings, weak proof anchors, and renderer differences.
4. Review semantic and rendered diffs.
5. Adopt existing paths only through an explicit write command in a clean worktree.
6. Run Murlocs checks and representative path explanations.
7. Remove legacy tooling only as a separate, reviewable cleanup after rollback has been tested.

The bootstrap skill may help interpret genuinely repository-specific policy, but the known legacy
schema conversion should be deterministic. Agent judgment must not be required merely to rename
fields or preserve existing structured intent.

Compact repository-derived fixtures preserve the shared contract in Murlocs CI. A live read-only

## v0.2b result

The migration workflow now provides read-only inventory and semantic/rendered diff, candidate TOML
generation, explicit adoption with byte-exact legacy-map preflight, recoverable legacy pruning, and
hash-guarded rollback. Full live Chirp and Kida inventory and semantic diff remain read-only pilot
checks; adoption is exercised only in isolated fixture repositories until each project's proof debt
is resolved in v0.2c.

## Pilot acceptance criteria

The v0.2 pilot is successful when:

- all 58 maps, 99 invariants, 65 checks, and existing graph edges are accounted for;
- search policy, judgment, ownership categories, review triggers, and context budgets survive;
- every weakened, missing, or remapped proof is visible in machine-readable output;
- import performs no implicit ownership transfer and adoption refuses dirty or ambiguous targets;
- neither repository's user-owned `CLAUDE.md` is modified;
- both legacy verifiers pass immediately before adoption;
- Murlocs passes afterward and `explain` returns the expected chain for representative root, source,
  nested-source, test, documentation, and operational paths;
- rollback restores the pre-adoption instruction network exactly.

Only after both repositories meet the same acceptance contract should Murlocs generalize adapters
or use a third repository as validation.

## Proof-anchor audit: location is not proof

During the furatena migration rehearsal ([#179](https://github.com/lbliii/murlocs/issues/179)),
Murlocs surfaced a check that had been green under legacy location-only verification:

```toml
[check.changelog-draft]
invoke   = "make changelog-draft"
location = "changelog.d/README.md"
```

`changelog.d/README.md` is contributor prose about fragment naming. It does not define,
reference, or prove the `make changelog-draft` target — that definition lives in `Makefile`.

Because the file existed, a location-only scheme reported success. Murlocs's required
`proof_contains` anchor forces the question *"what string in that file proves this?"* and
there was no answer. The upstream fix is to point `location` at `Makefile` and anchor on the
target definition:

```toml
[check.changelog-draft]
invoke = "make changelog-draft"
location = "Makefile"
proof_contains = "changelog-draft:"
```

This is the clearest evidence so far that the proof-anchor requirement earns its cost: decorative
wiring can stay invisible until something asks for the actual proof text.
