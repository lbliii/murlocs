# Synthetic 91-map scale pilot

Measurement date: 2026-08-03

This pilot exercises one deterministic Murlocs network above the 80-map threshold without copying
guidance from a private repository. It is a bounded mechanics test, not evidence that one synthetic
topology represents every large codebase.

## Fixture

`benchmarks/scale_network.py` generates a disposable repository with:

- 91 scopes and generated maps: one root plus nine ten-scope domains;
- mixed width and depth, including three sibling services and a six-map root-to-leaf chain;
- nine owner-focused domain layers and one architecture overlay;
- six distinct owners, with exact CODEOWNERS entries for the root manifest and every layer;
- one accepted point-of-view override and one cross-adapter edge per domain; and
- source coverage, command-backed domain invariants, evidence anchors, and a 24,576-byte budget.

The generator is deterministic. Its compiled map-and-lock snapshot hash was
`673bd438f5300be40569128bd8fa19016522d08806680d77ccd5d8469c5dd53e`, and a second compilation
produced identical bytes.

Run the complete pilot in a disposable directory:

```bash
uv run python benchmarks/scale_network.py --samples 5
```

To inspect the generated repository, versioned evaluation inputs, and raw evaluation result:

```bash
uv run python benchmarks/scale_network.py \
  --samples 5 \
  --artifacts /tmp/murlocs-scale-artifacts \
  --output /tmp/murlocs-scale-results.json
```

The `repository` and `evaluation` targets below `--artifacts` must be absent or empty. The command
refuses a non-empty target before writing so it cannot replace an existing repository or result set.

## Measured result

The checked-in result is the direct JSON output from the generator:
[`scale-network-results.json`](scale-network-results.json). It was recorded with CPython 3.14.3 on
an arm64 Mac running macOS 26.5.2. Runtime uses five wall-clock samples without allocation tracing;
peak Python allocation is measured in a separate instrumented invocation so tracing overhead does
not distort the runtime samples.

| Operation | Median | Range | Peak Python allocation |
| --- | ---: | ---: | ---: |
| `compile` | 615.280 ms | 546.029–631.122 ms | 442,836 bytes |
| `check` | 509.724 ms | 493.452–657.528 ms | 442,737 bytes |
| `explain` | 9.357 ms | 9.236–12.077 ms | 306,332 bytes |
| `impact` | 30.181 ms | 29.905–31.107 ms | 323,967 bytes |

These are observations, not test thresholds. CI asserts structural outcomes and positive
measurement shape; it does not assert machine-specific latency or allocation totals.

The 91 maps contain 77,813 generated bytes in total. The largest chain according to Murlocs' budget
calculation is 13,846 bytes, or 17.79% of the total and below the 24,576-byte limit. Evaluation input
adds separators between maps, so the exact scoped prompt is 13,856 bytes; the corresponding inline
dump is 77,993 bytes.

## Governance behavior

The deepest representative `explain` trace contains root, domain, platform, runtime, adapters, and
HTTP scopes. The HTTP scope reports both its `@team-delta` domain layer and the `@architecture`
overlay, including the accepted override.

A change to the HTTP target requires review from five owning ancestor scopes, recommends its one
edge-connected queue scope, and leaves 85 scopes unaffected. A root manifest change requires all 91
scopes. This demonstrates focused fan-out for a local change while preserving global review for a
control-plane change.

The pilot also applies isolated mutations and then restores the valid fixture:

| Mutation | Expected detection |
| --- | --- |
| Edit a generated leaf map | `drift` finding |
| Replace a domain's CODEOWNERS owner | `ownership` finding |
| Lower the active-context budget to one byte | `budget` finding |
| Make the overlay change an existing scope path | manifest load refuses the immutable-path override |

## Recorded-run evaluation

The generator creates a versioned task and three recorded-run inputs, then passes them through the
normal `murlocs.eval --task ... --runs ...` ingestion path. The objectively checked task asks for
the owner and invariant applicable to the HTTP target. All three arms include both required facts,
so every efficiency result clears the correctness gate.

| Arm | Correct | Executable steps | Files inspected | Lines inspected | Guidance bytes |
| --- | --- | ---: | ---: | ---: | ---: |
| no guidance | yes | 12 | 12 | 680 | 0 |
| inline dump | yes | 4 | 1 | 2,474 | 77,993 |
| scoped Murlocs chain | yes | 3 | 2 | 306 | 13,856 |

This is a deterministic scripted walkthrough designed to prove ingestion, correctness gating, and
the search-versus-context calculation. It is not a live-model trial and does not establish that
Murlocs guidance improves agent performance in general.

## Practical conclusion and limits

For this 91-map network, compile and check completed in under one second at the median, read-only
path queries completed in tens of milliseconds, the deepest chain stayed below budget, and all
governance failure modes remained visible. That supports using Murlocs for a network of this
measured shape.

The pilot does not establish behavior beyond 91 maps, validate private-repository semantics, cover
every possible graph topology, or replace repeated live-model trials across real tasks and models.
Those claims require separate evidence.
